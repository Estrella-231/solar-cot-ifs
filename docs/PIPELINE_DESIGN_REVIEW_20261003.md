# 全链路设计复查与改进优先级（2026-10-03）

范围：第二篇湖南 S→R→H 链及新月度划分。依据当前代码、保存的实际结果与预处理元信息；本次没有修改训练代码、提交作业或读取新test。配套详细实现见 [交接文档](END_TO_END_HANDOFF_20261003.md)。独立完整性审查结果另存于本次审查目录，设计建议不等于已证实的误差归因。

## 总体判断

保留按月连续留块、缓冲、train-only归一化、区域/局地空间场、历史轨迹、同键配对评价。这些方向合理。目前更明显的问题是各阶段优化目标及支持域不一致：S学习全图归一化AGRI，R学习筛选白天像元的log-COT，区域H学习kt，最终却按站点15分钟GHI验收。全链一致性应先于进一步扩大网络。

## P1：区域H的损失重新退回kt域，值得最先纠正

证据：`scripts/train_regional_cot_ghi_pilot_20260927.py:201` 用加权kt MSE；较早 `scripts/train_causal_cot_trajectory_solarresnet_v5.py:52` 已在GHI域计算误差。

因为 `GHI_hat=kt_hat×Gcs`，所以

```text
(kt_hat−kt)² = (GHI_hat−GHI)² / Gcs²
```

若GHI误差相同，Gcs=20的样本对kt MSE的贡献是Gcs=800样本的1600倍（假定其他权重相同）。这会把低晴空辐照度时段赋予很大的隐含权重。

这不是只有数学上的担心：旧头的实际残差分解中，约5.7%的Gcs<20训练行贡献了95%～99%的kt损失，但仅占约0.02%～0.06%的GHI平方误差。证据为 [历史分解](HEAD_LOSS_MASS_RESULTS_20260910.md) 和 `audits/head_loss_mass_20260908_v1/loss_decomposition.json`。这些比例属于旧头，不能直接冒充区域头的实测比例；区域头需要重算自己的贡献分布。

建议：新H仍可输出非负kt，但主损失用区间GHI域，例如 `sum(w×((kt_hat×Gcs−GHI)/1000)²)/sum(w)`。先做相同输入、架构、行键和更新预算的单因素对照；不通过删清晨样本、裁kt或事后改评价掩膜制造提升。

## P1：必须确认输入云图在初始化时刻是否已经可取得

预处理元信息把文件名标称UTC作为几何时间；示例HDF文件时间区间是00:00:00～00:14:59，另保存逐扫描行观测偏移。当前读取器没有将扫描结束/文件可用时间作为输入因果门禁。

如果把00:00名义云图当作00:00可用输入，而站点所在行实际在之后扫描，第一段(00:00,00:15]标签可能与输入的实际观测时段重叠。**这里是待核验的业务因果风险，尚未证实全部样本发生泄漏。**本次没有原始全时期到达日志，不能凭文件名就定案，也不能直接改已授权的canonical坐标。

建议：从现有train/val aux抽取真实观测偏移，核对原始HDF扫描起止及生产延迟；区分名义初始化和最早可发报时刻。主张实时业务预报之前，必须证明使用的输入在发报前已经可获得。观测时间仍用于15min结束窗口标签，不能为配合图像而改成瞬时scan GHI。

## P1：新旧划分的S/R/H仍处于过渡期

新S已按新月度清单训练，现有R及区域H是旧划分探索资产。旧R/H可能已经接触新val/test中的日期。即使给它们换上新S，也不能把整条链标成新合同独立评价。

建议：新日期映射贯穿CPP配对、R归一化/训练、S→R侧车、GHI标签和H训练。诊断可以保留历史模型，但每份输出明确版本；新test等整链冻结再打开。新旧模型横向对比只用双方都未训练过、且符合当前读取授权的共同验证窗口，并在相同物理单位及掩膜下重算。

代码层面不能只替换manifest就执行旧下游：CPP配对器仍断言旧日期范围（`pack_regional_agri_cpp_bank_20260926.py:140`），区域R断言旧6293/3488样本数（`train_regional_r_full_20260926.py:145`），GHI bank读取旧S配置及旧标签pack（`build_regional_cot_ghi_pilot_20260927.py:95`），标签join绑定旧hash和行数（`join_forecast_labels.py:20`）。这些断言应保留为历史保护，新合同应另写配置/入口及对应审计，不应直接删掉断言绕过。

## P2：S的目标与站点白天GHI关系偏弱

证据：`scripts/train_monthly_simvp_20261002.py:120` 对所有时效、13通道和有效像元做pooled MSE；目标valid来自AGRI质量位及有限性，未按白天、站点邻域或云事件单独加权。等季节选模减小季节样本量差异，但没有解决目标量不同的问题。

全图误差下降可以来自背景、晴空或夜间，而关键站点云边缘/到达时间仍错误。该结构本身有空间建模能力，不能由损失直接断言它必然模糊。

建议先增加不训练的验收：白天逐波段物理误差、逐lead站点64邻域、厚云事件峰值/位置/到达/消散，再决定是否需要独立的白天或站点/云结构监督候选。现有新S保留为固定基线；不把多种损失、DOY和新骨干同时加上后称单因素改进。

两段8帧共用网络，第二段输入为第一段预测（`triad_models.py:197-201`）。这是合法的训练方式，但应专查+120到+135的误差变化、后半段平滑和误差累积；尚不能未经图像诊断把它认定为当前失败主因。

## P2：R训练与部署时的输入分布、太阳高度支持域不同

R配对监督只接受全部13通道有效、day_mask有效且SOZ<80°的像元；H旧标签接受SOZ<90°且clear>0，历史序列还可能跨夜间。R在这些域外时段也会输出Softplus正值，数值存在不等于可靠反演。

另外，R训练输入是真实AGRI，未来部署输入是S预测AGRI。预测偏差、平滑及通道间不一致可能被R放大。`R(真实未来AGRI)`更准不能推出`R(预测AGRI)`自然可靠。

建议：先以太阳高度、真实/预测输入域、lead、COT强度分层，检查R偏差。COT输入可增加由历史QA及已知太阳几何形成的可靠性标识；当前H所谓validity只是时间前缀标志（`train_regional_cot_ghi_pilot_20260927.py:52-55`），不是物理质量标识。未来真实QA不能用于可部署输入。是否做预测域适配应另立实验，保持监督及来源边界。

log1p域Huber使厚云大幅值误差相对被压缩：这可能影响峰值，但并不意味着改成物理COT MSE必然改善GHI。应将厚云漏报、晴空误报及对应GHI损失联合验收。

## P2：格点对齐不等于遮光路径对齐

AGRI与COT在同一格点处理是必要的，但地面站点被遮挡的云不一定就在其名义正上方：存在卫星视差、云高与太阳方向造成的阴影位移。当前区域H代码没有显式云高/阴影投影模块，cosSOZ/cosRAA也不等于已经做了位置修正。

这类机制有独立原始研究依据，见 [Wiltink等，AMT 2025](https://amt.copernicus.org/articles/18/3917/2025/)。该文结果不构成本项目纠正后的预期收益；其结论也不支持只加单项修正必然更好。

建议：在实际云事件上先做影子方向/空间偏移敏感性诊断。未来参考对齐只能归因，不能算预报成绩。没有可靠云高前，不凭空加入固定高度投影并声称更物理。

## P2：H保留了空间，但仍未显式定义“经过站点的15min云过程”

当前COT分支是四层因果3D卷积和位置保留的Flatten，已没有全图GAP。不能继续把效果小归咎于“又做了全图平均”。不过：

- 区域256→32的8×8池化确实降低上游细云团/云边缘分辨率；局地64保留细节，但较远来源只有粗背景。
- 当前lead的图像分支只见当前目标图；COT虽然有前缀轨迹，读出仍在该lead结束帧，没有显式区间积分。
- 3D卷积具有学习运动的能力，但未输出或约束云到达时间、源位置和演变。

建议先画池化前后的同一上游云团，以及前一目标帧到本目标帧间的真实GHI区间；再单独比较端点读出与区间内时序聚合。不要把扩大网络当成已经解决物理对齐。

## P2：H的训练侧车可能比验证侧车更容易

既有GHI bank用训练好的S生成同一S训练清单内的预测，再训练H；未实现按日期折外S预测。相同情况也可能出现在R的训练域反演。H可能学到“训练内预测更好”的误差分布，部署面对更差的外推图。

这是需要测量的堆叠模型分布差异，**不是自动认定test泄漏**。先比较train/val分层外推误差及COT分布；若差异大，再考虑训练内部日期交叉拟合或独立校准分块。不要一开始就盲目做大量S重训。

## P2：区域H的最少更新次数并未被代码保证

`minimum_updates`只提高最大epoch数，但`stale>=patience`仍可提前停止；因此报告中不能把600次当所有组都真正完成的下限。各组早停还会产生不同实际优化步数。

新H应保存实际optimizer_step，并规定达到最少步数后才允许早停；做固定预算对照时明确比较规则。profile记录了吞吐，但按显存选最大batch也不等于选择最快或最适合优化的batch。

## P3：划分本身合理，评价解释仍要收紧

按月两天val、两天test和一天buffer符合本轮目标，不建议继续随意改日期。它提供季节覆盖，不是严格未来整年外推；一日缓冲保证本项目窗口隔离，但未证明天气事件独立。相邻初始化重复看到同一目标时刻，应按日期/事件分块估计不确定性。

每月只有一块两天验证，可能由一个天气过程主导。固定清单后补充月/季/站点/lead分层、覆盖率、按事件块的配对区间即可，不按当前成绩再重抽好看的日期。12epoch和单seed是预算完成，不是充分收敛或稳定收益的证明。

## 推荐执行顺序

1. 在新train/val元数据及小样本上完成输入可用时刻、15min标签和晴空分母审计；同时记录R的太阳高度有效域。
2. 对已训练新S做固定验证诊断，不改它：真实图/预测图、区域与局地、逐lead/季节/事件，检查长时效与两段接缝。
3. 按新划分重建R及侧车；先证明真实输入反演与预测输入反演分别有什么误差。
4. 新H输出kt但主损失回到GHI域，补实际更新计数；先用相同预算做zero/forecast及单列oracle，再做必要归因。
5. 物理投影、时间积分、预测域适配按诊断逐项试，不同时改所有模块；IFS在因果来源验收后独立增加。

最先值得修的是目标、时间和来源一致性。换骨干、增加通道及更多GPU都不能替代这三项。
