## 主要发现

### P0：历史 NC 与 V2 写出合同不一致，生产来源仍未闭环

`Retrieval_CPP.py` 把 `QA` 列为必需变量，并在新文件中创建 `QA(LAT,LON)`。现有 2025 年样本只有 `LAT/LON/CLP/CTH/CER/COT`，没有 `QA`；其全局属性也为空。

影响：无法用这份包解释历史文件采用的确切代码提交、回填规则、运行参数和输入文件。论文中只能把现有 COT 描述为外部 FY4B CPP 产品，不能声称已经复现其生产过程或完整质量控制。

需要生产者补充以下任一闭环证据：

1. 实际生成 2025 历史 NC 的 V1.1_122 代码快照、权重哈希、运行配置和日志；或
2. 用当前 V2 对若干历史时次重算，提供逐像元对比、原始 AGRI/ERA5/LCCS 输入清单及差异解释。

### P0：上一小时结果允许连续链式回填，但只有布尔 QA，没有回填年龄

当任一 AGRI 红外通道或 SAZ 无效时，代码把上一小时同一像元的 CLP/CTH/CER/COT 全部复制到当前时次。整景读取或推理失败时，也会把上一小时结果作为当前整景结果；下一小时又可以引用这个已经回填过的文件，因此陈旧值可以连续传播。

V2 的 `QA=1` 只能说明当前像元来自上一份文件，不能区分它是 1 小时前的原生结果，还是已经链式传播多小时的结果。历史 NC 又没有 QA，所以无法从现有训练数据识别这种回填。

影响：如果历史生产也使用了同类逻辑，有限值筛选会把陈旧 COT 当作当前 COT，形成时间错配，并可能造成连续时次平坦、重复或错误天气归类。现阶段不能断言历史文件一定发生过该回填，只能确认当前 V2 有这个机制且历史产品缺少可审计标志。

建议生产代码增加 `source_observation_time` 或 `fallback_age_hours`，保留 `observation_invalid`，并限制最大回填年龄。论文数据侧在获得 QA 后应把回填像元排除出主实验，单列敏感性分析。

### P1：便携包按当前目录状态不能直接运行

八个几何/索引资源位于 `Auxiliary_Data/105E.zip` 和 `133E.zip` 内，而适配器直接读取 `Auxiliary_Data/*.npy` 和 `*.nc`。README 没有要求先解开这两个嵌套压缩包。`sha256sum -c MANIFEST.sha256` 在当前目录会把八个资源报告为缺失；预检查只验证辅助目录存在，没有逐文件验证，因此也不能提前给出准确错误。

此外，preflight 即使只选择 FY4B，也会无条件检查 FY、GOES、MSG 和 ERA5 四类数据根目录。便携包已经删除 GOES/MSG 入口，新机器没有这两类目录时，FY4B 单星命令仍会在预检查阶段失败；相反，实际必需的 LCCS 根目录和所选星下点辅助文件却没有被逐项检查。

本次已从两个嵌套 ZIP 的数据流计算哈希，八个资源均与 `MANIFEST.sha256` 一致，资源本身没有损坏。问题是打包布局和部署说明不一致。

建议：在 README 增加安全解压步骤，或直接以散文件交付；让 preflight 只检查所选卫星真正依赖的数据根目录，并逐项检查 LCCS、索引和 SAZ 文件。

### P1：NC 未保存足够的 provenance

V2 写出的 NC 仍未记录：

- `run_time` 的 UTC 语义和原始 AGRI 观测时间；
- 被选择的 AGRI 文件路径/哈希（同一时次有多个匹配时当前代码取排序后的第一个）；
- ERA5/LCCS 文件和有效时刻；
- 代码版本、模型权重哈希、归一化版本；
- 星下点配置和回填源时间。

这些信息只可能出现在结构化日志，而便携包明确没有附带历史日志。只要日志与 NC 分离，文件移动后仍会失去绑定。

建议把上述关键字段写入 NC 全局属性，并生成逐文件 manifest。日志用于详细诊断，NC 自身至少要能独立确定模型、输入、时间和质量来源。

### P1：输入文件匹配过宽

FY4B 输入使用 `*YYYYmmddHHMM*` 匹配并取字典序第一个文件。若目录中同时存在多个版本、分段或重复下载文件，结果依赖文件名排序；选择结果只写日志，不写 NC。

建议校验产品名、分辨率、观测起止时刻和版本，并在匹配数不为 1 时停止或按显式优先级选择。

### P2：缺测值在归一化前被替换为物理量 0

数据集先把 NaN/Inf 替换成原始数值 0，再执行 `(x-min)/(max-min)`。因此缺测亮温不会成为归一化零值，而会成为明显负值。最终坏像元会被掩膜或回填，但异常输入仍参与卷积并可能影响邻域；ERA5/LCCS 的非有限值也没有进入 `observation_invalid`。

建议先归一化，再把非有限值替换成归一化零值，并把所有 16 通道的有效性纳入质量检查。修改前要用相同样本做像元级回归对比，避免无依据改变既有产品分布。

### P2：运行环境不可完全复现

`requirements.txt` 未固定版本；`torch.load` 没有使用 `weights_only=True`；包内明确排除了测试。当前能确认所有 Python 文件通过 AST 语法解析，但无法从包内独立重建原生产环境，也没有自动测试证明 V2 与 V1.1_122 数值等价。

建议提供 Conda lock/容器镜像、Python/CUDA/PyTorch/netCDF4 版本、最小金标样本及其输出哈希。权重加载在兼容的 PyTorch 版本上改为 `weights_only=True`。

## 已确认的数据合同

- FY4B 2024-03-01 01:00 UTC 之后走 105E 配置；2025 年输出经纬度为纬度 `81→-81`、经度 `24→186`。
- 卫星输入：AGRI C11、C12、C13、C14、C15，加 1 个 SAZ。
- 环境输入：300/500/850/1000 hPa 温度、四层相对湿度、SKT、IGBP LCCS，共 10 个通道。
- 模型总输入为 16 通道，采用固定 min-max 常量。
- 模型为四个 SmaAt-UNet：CLP、CTH、CER、COT；COT 反归一化到 0–100，最后写出时有云像元限制到 0.01–100，晴空像元置 0。
- 4051×4051 网格按 128×128 tile、步长 64 重叠推理，再用 sigmoid 权重融合。
- 两个嵌套 ZIP 中八个辅助资源的 SHA-256 均与清单一致；四个模型权重也全部与清单一致。

1. 暂不因为这份代码推翻已经完成的 A/AC 结果；它没有证明历史 COT 数值错误。
2. 主文中不要把现有 COT 写成“已验证无回填、具有原生逐时观测质量标志”的产品。
3. 立即增加历史 NC 的时序重复/平坦扫描，重点统计站点 16×16 patch 在相隔 1 小时及连续多小时的完全相同率；这只能筛查疑似回填，不能替代生产日志。
4. 向生产者索要历史 V1.1_122 代码和日志，或请其用 V2 重算一小批覆盖晴空、多云、整景缺测和高 COT 的时次。
