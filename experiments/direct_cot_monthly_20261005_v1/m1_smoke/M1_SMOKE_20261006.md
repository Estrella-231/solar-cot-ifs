# M1 直接 COT 工程烟测记录

日期：2026-10-06。范围：月度新合同 `hunan_monthly_block_2d_buffer1d_seed42_v1`；仅工程连通性检查，不作预测技能结论。

## 运行

- PBS：`212189.tc6000`，node22，NVIDIA A800-SXM4-80GB，单卡；正常结束。前一次 `212187.tc6000` 在 Python 导入 `hunan_data` 前因 CLI 路径参数错误退出，未开始训练；修正为模块文件路径后重跑。
- 8 个窗口全部来自 train split（2025-06 至 2025-09），每个含8张历史AGRI输入及16个未来CPP目标。验证及测试载荷均未进入训练；训练也未加载未来AGRI。
- 200次更新，batch=2，seed=42；模型宽度96，共2,307,321参数；目标为有效mask上的逐时效等权 `MSE(log1p(COT))`。
- 训练损失从2.9332降至0.4027；因只使用8个窗口并训练200步，该变化仅说明可反传和小样本可拟合，不是验证表现或泛化证据。
- 无效标签扰动导致loss变化为0；GPU checkpoint重载后最大预测差为0；mask有效比例99.21875%。峰值显存2,357,687,296 bytes（约2.20 GiB），记录的GPU峰值分配约2.36 GB；训练更新阶段约9.62秒。
- 随后在同一A800上完成包含新读取AGRI/几何文件的batch profile。最终 profile 使用8个train窗口循环用于系统计时、丢弃不完整尾批；没有把重复窗口作为效果评估。batch48吞吐104.6样本/秒，batch56为104.2，batch72为100.6；batch72仍在最高吞吐的5%以内，是符合≤85%显存门槛的最大已测批量。batch72峰值66,089,857,536 bytes（约61.6 GiB，占80 GiB卡约77%，余量约18.4 GiB）。数据读取时延有波动，故该吞吐只作预算估算。按35,320个训练窗口、12轮、batch72折算约5,892次更新，粗略约70分钟更新时间，不含初始化、验证和完整数据存储开销。
- 训练因果输入为历史13通道AGRI与8帧历史/16帧已知太阳几何；未来AGRI和未来COT没有进入前向输入。CPP仅作为masked训练标签。

## 判定与限制

M1 engineering smoke及单卡batch profile通过。profile读取了实际训练AGRI/aux文件，但仅由8个训练窗口重复构成，不覆盖全量数据的I/O缓存和CPP监督准备耗时。下一步是完成新合同训练/验证集的全区域CPP有效监督覆盖与厚云样本统计，并冻结可用支持域、目标bank和训练manifest；通过该门槛后才启动12轮D_CPP筛选。既有CPP产品仅约覆盖31%的train目标时刻、验证约33%，因此任何后续正式结果都须显式限定在可用支持域。
