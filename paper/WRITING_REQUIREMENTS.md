# COT论文写作要求：科学问题、证据与叙事

生效日期：2026-10-15。适用于英文正文、中文对照、摘要、图注及论文计划。依据用户要求和[代表性文献阅读](references/narrative_review_20261015/README.md)制定；这是编辑规范，不新增实验审批流程。

## 1. 主线与贡献层次

核心问题：从卫星多光谱观测得到的显式云光学厚度表示，能否改善站点GHI估计？改善出现在哪些云况、能否在另一地区重复、在未来输入存在误差时还保留多少？

叙事顺序为：物理问题 → 可检验问题 → 对照设计 → 总体结果 → 条件差异及解释 → 预报应用与适用边界。研究过程中的部署、调试、修复、验收顺序不得成为论文目录。

主要贡献是COT辅助GHI估计的实证与条件分析；预报是应用检验。外推网络创新和IFS扩展不承担本篇主线。COT由同一AGRI经反演器得到，不能称作新增独立观测；它可引入云属性监督形成的表示和先验，其增益需要对照验证。

研究范围为湖南两站与湖北三站，共五站。两区域独立训练和区域内时间留出评价，称独立区域重复验证，不称零样本迁移。五站是研究设计；在结果未齐前，不写成五站都已经有效。

## 2. 章节与段落写法

- 摘要：具体问题和缺口、方法核心、评价范围、最关键实测结果、结论。先写已支持的结果，不以预期正结果补齐摘要。少用泛化能源背景。
- 引言：云对地表辐射的影响和卫星估计困难 → 已有多光谱/物理属性方法解决了什么 → 显式COT相对已有多光谱信息的增量仍需什么证据 → 本文研究问题与比较设计。已有方法使用过COT时不得虚构“首次引入”。
- 方法：按数据的物理意义和映射关系讲述观测、COT检索、局地融合、GHI输出；每个模块解释输入、输出、作用及关键运算。必要网络维度用一张表，避免逐文件逐函数介绍。
- 实验设计：说明共同样本、日期划分、归一化、基线、训练预算与选模、指标和不确定性；将实现细节集中说明，避免在每个结果段重复。
- 结果：每节回答一个问题。一般用“结果判断 → 数字/图表 → 有证据的解释”组织段落；不逐行复述整张表，不按作业启动时间组织。结果不足时直接说明，不将观察强写成机制。
- 讨论：解释收益的条件性、可能原因、与文献关系以及可推广范围。对光学厚度、云位置、空间代表性和外推误差分别讨论；没有控制证据不得指定唯一原因。
- 结论：回答引言问题，保留最关键量化证据和适用范围，不罗列开发成果或新增未经论证的主张。

一个段落围绕一个中心判断。无需机械地在每段末尾添加免责声明；影响理解的限定随结论出现，公共限制集中在数据/评价节和讨论中。

## 3. 对照名称

正文、图例和表头使用可读的输入/方法名称；内部ID仅在复现映射表出现。

| 内部ID | 正文英文名称 | 中文名称 | 用途 |
|---|---|---|---|
| A | AGRI baseline | AGRI基线 | 不加COT |
| AC | AGRI + COT | AGRI与COT融合 | 显式COT表示 |
| AP | AGRI + auxiliary features | AGRI与辅助特征 | AGRI派生的可学习辅助表示，控制头部容量 |
| AL | AGRI + retrieval features | AGRI与反演特征 | 冻结反演器隐藏表示，检查共享反演监督/特征贡献 |

共同太阳几何在表注和方法统一声明，不把AGRI baseline误解成没有几何。AP的容量匹配范围是可训练GHI头，不宣称整个反演系统参数完全相同。这些是同一估计框架的输入/表示变体，不包装成四种独立新算法。新增实验先核实输入语义再命名，不因缩写相同就沿用历史定义。

## 4. 语言规则

1. COT译为“云光学厚度”，无量纲；不等同云几何厚度或云顶高度。retrieved COT指反演值，CPP-derived/reference COT指参考检索产品，不能无条件称真值。
2. 同期GHI任务用 irradiance estimation（中文可称辐照度估计/反演）；未来用 irradiance forecasting。目标时刻真实AGRI产生的COT不能成为业务未来输入。
3. 加入COT输入称 COT-assisted / COT-augmented；只有明确的物理方程约束、结构或损失时，才进一步论证 physics-informed 的用法。
4. 使用具体动词：估计、融合、比较、降低、增加、关联。删除没有操作定义的“赋能、闭环、全链路打通、多维协同、全面提升、物理一致性增强”。
5. “显著”“稳健”“普适”“证明”“最优”必须有相应证据。区间跨零不证明等效；单个厚云组大幅改善不证明随厚度单调增加。
6. 相对误差降幅写清分母：100×(RMSE_baseline−RMSE_variant)/RMSE_baseline；绝对差保留W m⁻²。COT误差不能标为W m⁻²。不要把RMSE降低3%称“准确率提高3个百分点”。
7. 不把架构、特征来源等同时变化的结果归因于单个因素。预报收益衰减可以提出外推误差假设，不能未经配对诊断就把所有退化归咎于外推器。
8. 先讲结果和意义，再给必要技术细节。英语避免臃肿名词串，中文避免直译工程术语；中英文保持相同证据强度。

## 5. 信息放置

| 信息 | 正文处理 | 其他位置 |
|---|---|---|
| 物理输入、局地尺度、太阳几何、R与GHI的运算 | 必要方法内容 | 详细层表可放补充材料 |
| 15分钟标签区间、时间对齐、日期划分、训练期归一化 | 明确且可复现 | 完整日期清单另存 |
| 配对样本、白天/质量筛选、参考覆盖、置信区间方法 | 必须保留 | 全站点/全时效细表补充 |
| 训练预算、优化器、随机种子、选模原则 | 一处集中报告 | 完整配置与代码公开 |
| 服务器路径、PBS号、GPU占用、文件哈希、PASS/witness/收据 | 不进入科学叙事 | 工程日志与复现清单 |
| 错误排查、旧版本失败、修复时间线 | 不写开发日记 | 工程历史；影响科学解释的限制另作概括 |
| 同期/预测输入、validation/test区别 | 正文必须清楚 | 不可因精简而省略 |

“合同”在论文中按含义改成“统一实验设置/数据定义”；“门禁通过”改成实际科学做法，例如“所有方法在同一站点和目标时刻比较”。不是简单替换词，而是删除无科学作用的信息。

## 6. 图表叙事

每张图必须对应研究问题。推荐：区域与方法示意；各站总体对照；厚度分层及样本支持；连续真实AGRI/COT/GHI案例；预报时效与COT误差传播。同期与预报结果分面或分图，不能靠一个总标题混合。

事件图展示同一日期连续云图、COT和15分钟GHI曲线，含成功和失败情形；个例解释现象，不能替代总体评价。合成图只能说明结构，明确标注示意；不得充当实际云场证据。表格用科学名称，不用运行目录、任务状态和版本号替代方法名。

## 7. 本项目改写示例

工程写法：“Txx完成，三seed witness PASS，bank和pack已闭环。”
科学写法：“采用相同样本和训练设置比较加入COT前后的GHI估计误差，并汇总三次随机初始化结果。”具体数值在结果节给出。

过强写法：“COT显著改善预报，退化完全由外推限制导致。”
科学写法：“我们分别评价同期COT辅助估计与未来输入下的预报表现，以检验COT表示的增益及其对外推误差的敏感性。”结果未确定前使用问题式陈述。

模糊写法：“厚云提升22.45%，证明物理属性普遍有效。”
科学写法：“在CPP参考产品覆盖的厚云子组中，加入COT后的GHI RMSE降低22.45%；该子组包含173条记录、25个日期。”统计范围和解释在相邻正文交代，不推广至所有厚云。

## 8. 写作检查（无需额外审批）

- 每节是否回答一个科学问题，而非说明做了哪些工程任务？
- 输入、标签、预测时刻和对照名称是否一眼可辨？
- 数字是否有对应保存结果，单位/样本支持/统计范围是否一致？
- 五站、厚云和未来预报的结论是否分别有证据？
- 是否将科学限制说清一次，而非反复防御性铺陈？
- 是否把同一研究范围内的新旧结果按可比性组织，而非只保留有利结果？
- 中英文是否同步，摘要、图表、正文结论是否一致？

本要求只改变表达与论证组织，不改变数据划分、不重跑已完成实验、不赋予缺失结果正向结论。
