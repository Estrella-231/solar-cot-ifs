# 原论文截图与上一版的具体格式差距

2026-10-30。本轮逐张重新打开了6张原论文/用户示例截图，以及我方结构图、云事件图、预报图。以下不是重复上一份原则清单，而是按肉眼可见的版式逐项对比。原图来自既有PDF直接渲染裁片，本轮复制到 `reference_crops/` 并核验与原裁片字节一致；完整页与原裁剪坐标保留在上一份图册。没有修改论文原图。

## 一、最优先修的不是颜色，而是架构图的构图

上一版结构图没有达到用户给的样例格式。它是一张177×188 mm的纵向说明图，宽高比约0.94；原Chen Fig.4截图宽高比2.36，Cloud-FNO Fig.1约1.90，用户Baguan示例约2.42。上一版将R全部层级、双分支、控制差异分别排成三层，导致“我先看哪里、数据长什么样、核心贡献在哪里”不突出。

### 1. Chen Fig.4：真实图像输入＋分支对应＋合流读出

**正式论文**：Chen et al., *Applied Energy* 352 (2023), 121979，PDF第6页Fig.4，[DOI](https://doi.org/10.1016/j.apenergy.2023.121979)。原图：`reference_crops/chen_2023_fig4_architecture.png`，完整页：`../20261030_figure_atlas/chen/chen_page-06.png`。

![Chen Fig.4原图](F:/CODE_Classify/辐照度预报/solar-cot-ifs/paper/reviews/20261030_reference_redraw/reference_crops/chen_2023_fig4_architecture.png)

| 可直接看到的原图做法 | 我方上一版实际问题 | 下一版必须落实的改变 |
|---|---|---|
| 顶部不是“Input”文字框，而是不同波段的真实云场缩略图 | 输入仅写13 AGRI＋3 geometry，读者看不到空间对象 | 放一组真实AGRI缩略图与真实R-COT，图旁标清示例身份；图像不能冒充网络特征激活 |
| 波段图、各自编码器、各自Flatten严格同列 | 我方AGRI/COT路径虽分开，但框同形同色、视觉对象差别很弱 | 用蓝灰表示图像特征、青色表示COT特征；同位3×3裁块和各自编码紧邻 |
| 宽Concatenate把多个分支一次收束，右列只负责MLP输出 | 我方Concatenate、Flatten和MLP均是等大的文字框，操作主次不明显 | 合流处画两组规则特征薄片进入同一个拼接张量，再单列较小Flatten和读出 |
| 作者把重复分支用省略号压缩，整体是横向大矩形 | 我方将标准U-Net详细层级放成占半页的独立大面板 | 主图只保留R的身份与输入/输出，小型inset展开两级U-Net；不要给标准R比关键融合更大权重 |

**为什么作者需要此图：** 它的科学问题涉及波段选择，必须看清“各波段分别编码后怎样合并”。我们的科学问题涉及同源COT表示，必须看清“AGRI仍被保留，COT如何额外进入同一站点映射”。可借用分支—合流的构图，但不能把它的逐波段CNN/attention画成我方实现。

### 2. Cloud-FNO Fig.1：图像序列—网络—图像序列

**正式论文**：Zhang et al., *GRL* 53 (2026), e2025GL119553，PDF第4页Fig.1，[DOI](https://doi.org/10.1029/2025GL119553)。原图：`reference_crops/zhang_2026_fig1_architecture.png`，完整页：`../20261030_figure_atlas/grl/page04_original.png`。

![Cloud-FNO Fig.1原图](F:/CODE_Classify/辐照度预报/solar-cot-ifs/paper/reviews/20261030_reference_redraw/reference_crops/zhang_2026_fig1_architecture.png)

| 原图实际做法 | 上一版差距 | 应采用的对应形式 |
|---|---|---|
| 左右图像采用同样的透视堆叠，分别表示历史与未来；每排一个变量 | 我方流程图把8帧和16帧都写进矩形，序列数量只靠读文字 | 用少量实际帧堆叠，配8/16帧标签；首末时刻说明时间跨度，不必复制全部16张 |
| 中间网络用一个容器包住4层，层本身是窄的统一块 | 上一版每层均为大段文字框，没有“模型容器”与内部层级之分 | 外部用阶段边界，内部用编码器/层薄片；输入、模型、特征、物理输出采用不同形态 |
| 主要箭头方向从左到右，下排单独解释递推 | 我方U-Net、统计约束、控制接口和空间顺序混成三段竖排 | 主图横向完成一个任务；时间递推或对照定义放紧凑下排，避免把两种模型混合 |

**为什么作者需要此图：** 输出仍是空间场，其4类属性与输入时间序列都是核心对象；图像堆叠承担变量和时间身份，不是装饰。我们可以借堆叠表达历史/未来，但最终输出是站点标量，应以明确的站点读出结束，不能照抄区域GHI图。

### 3. 用户Baguan示例：阶段分工与局部融合展开

来源为**用户提供的手稿截图**，对应[arXiv:2603.14845](https://arxiv.org/abs/2603.14845)；截图含会议模板占位页眉，不能标成已核验的出版社终排。原图：`reference_crops/baguan_user_architecture.png`。

这里最应落实的是顶部的Stage 1 / Stage 2横向分区、多模态输入各占一条支路，以及重点融合模块在容器内展开。上一版只是将单一圆角框染了浅青色，没有这种层级差异。新版应把**图像预测、冻结反演、局地融合**分成清楚阶段，并把真正采用的concat或有符号残差展开；不能照搬其Q/K/V、Swin或天气基础模型。

## 二、结果图不是全盘重画，但需要更像“同一套论文图”

### 4. AMT Fig.11：紧凑2×2、统一时效、少量模型

**正式论文**：Papachristopoulou et al., *AMT* 17 (2024), 1851–1877，PDF第17页/刊页1867，[全文](https://amt.copernicus.org/articles/17/1851/2024/)。原图：`reference_crops/pap_2024_fig11_metrics.png`。

![AMT Fig.11原图](F:/CODE_Classify/辐照度预报/solar-cot-ifs/paper/reviews/20261030_reference_redraw/reference_crops/pap_2024_fig11_metrics.png)

它的4个面板分别为绝对误差、相对误差、相关和技巧分，全部横轴为预报时效，顶/底对齐紧凑，面板间距小，图例仅一份。原图总览并不漂亮到应逐色照抄，但其“同一横轴的一组互补问题”很清楚。

上一版预报图的2×2本身已合理，四臂科学身份也准确；差距在：上方长图例占两行，下排站名与长面板标题占过大空间，整图177×132 mm仍显得松散，绝对误差面板三条曲线近乎重叠、单靠它信息增量很少。

**下一版具体改法：** 若保持当前数据，做两列共同框架：左列“历史COT作用”，右列“未来COT作用”；上排各自逐时效配对差及区间，下排对应逐站差及区间。绝对RMSE转为同页精确表或小上排，不新增未计算的技巧分/R。缩短图例为已在图注定义的科学名称，固定两列的面板宽度与顶部基线，保留各自真实差值尺度并明确标明。这个改变是让每列回答一个问题，不是放大未来COT的微小差异来制造收益。

### 5. GRL Fig.3：时间横向排列，真值与预报上下成对

**正式论文**：同上Cloud-FNO，PDF第8页Fig.3。原图：`reference_crops/zhang_2026_fig3_spatial.png`。

该图每一列一个时效，每一组两行是真实产品/预报产品；物理变量拥有各自共享色条。读者沿横向即可跟踪云演变，再沿竖向比较误差。它的原图有48幅地图，信息很多，但小字过密、色标并不都理想，不能按数量照搬。

上一版事件图把**时效做成行、四种输入做成列**，这使读者需要竖读云演变，再转到下方横轴读时间；上方空间图和下方轨迹的阅读方向不一致。还有16×16图被放大到很大，三排空间图占大半张图，给人的信息量与占地不匹配。

**下一版具体改法：** 三列或四列固定关键时效，行按Observed AGRI / Forecast AGRI / Observed-image R-COT / Forecast-image R-COT排列；所有图保持同一站点十字和3×3框。下方两条全宽时间轴对应COT和GHI，并用同色竖向标记对应上方关键帧。可以比较真/预测的同变量上下差异，时间方向又与轨迹一致。使用原16×16像元，不能为模仿大区域地图增加伪经纬度线、插值细节或轮廓。

### 6. Chen Fig.6：云况案例图具有明确列语义

**正式论文**：Chen 2023，PDF第8页Fig.6。原图：`reference_crops/chen_2023_fig6_timeseries.png`。

原图三列依次为晴空、多云、部分多云，标题是站点和日期，观测为填充底，模型线覆盖；每行只保留一份轴标题，图例在顶端一行。它比“同一事件三站各一格”多出的科学信息是**列本身对应云况机制**，不是颜色更丰富。

我们现有三站同日图可作为补充，但不能因此宣称已经具备“不同云况对照”。下一版先保留当前合法事件，只把重复标签与空白压缩、共同图例放顶端；等已有明确云况规则和对应完整样本时，再增加一组互补事件。不得为了填满版式临时挑最漂亮的时段。

## 三、交付前的直接检查，而不是再写一份泛泛计划

1. **原图—新图必须并排给用户看。** 每张新版注明参考的论文、图号和采用的2–3条构图规则，不能只链接一本长阅读册。
2. 模型图先做到177 mm宽、约100–115 mm高。实际原图与特征薄片可见，主路径左→右；长说明转图注，不再出现188 mm高的三段式说明书。
3. 输入真实图像只作示例；符号特征薄片不伪装成已导出的激活；每条图像链的身份、尺度、时间和实际算子必须正确。
4. 结果图采用相同字号、字重、边线与面板标题规则。版式可以紧凑，置信区间、缺测断线、真实样本范围不能删。
5. 截图、旧版、新版应当能一眼看到构图变化；只有换颜色而框、留白和信息层级不变，不算按原文重画。

这次原图复看确认：**上一版的信息真实性比以前好，但视觉形式并没有充分落实已经分析过的原文设计，用户的批评成立。** 当前应先交一张真正改过构图的结构图及并排原图，再把确认过的视觉体系扩到其余图。
