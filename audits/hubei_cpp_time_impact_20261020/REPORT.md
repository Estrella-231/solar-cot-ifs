# 湖北CPP监督错时：R、COT与GHI结果影响核查

日期：2026-10-20。范围为10月14日起的湖北牛首、王寨、米庄独立区域实验，以及10月20日正确UTC四组实验。本次只核查已有train/validation元数据、文件哈希和保存的验证预测，未提交训练、未恢复定时任务、未修改论文正文，也未新读取test/buffer数值载荷。

## 结论

**此前湖北同期GHI的74.333→70.993 W/m²（4.49%）使用了8小时错配监督训练的旧R，不能继续作为有效COT物理表示收益的证据。** 10月17日“来源重建”“归一化重载”和10月18日“独立复算”都没有修正R的CPP时标；它们仍复用相同旧权重。

**10月20日四组实验的77.285→69.142 W/m²（10.54%）已确认使用正确UTC监督重训的新R。** 新权重→新COT数据→新GHI输入包→三个seed的哈希连接通过，并从保存的预测复算得到相同指标。但这是一套样本范围与容量控制设计均不同的新同期实验，不能把10.54%与旧4.49%的差直接归因于UTC修复。

**旧未来预报FAC也受影响：验证用全train R和训练输入用五折R均来自错时监督。本次核查范围内，正确UTC新R的湖北未来GHI配对实验尚未重跑。** 旧预报负结果不能据此推广成“正确COT也无预报价值”。

## 额外发现：历史CPP实际来源跨入缓冲日

按原冻结日期表对旧CPP的真实BJT来源日期重算，旧3,479行中有69条train输入、34条validation输入，实际取到的是**buffer日期的CPP来源**。其中38条train、13条validation被旧监督资格清单标为有效，分别包含9,728、3,328个有效CPP像元。本次元数据核查未发现这批CPP来源落在冻结test日期。

因此旧工程的`test/buffer=0`计数只能说明它按错误的AGRI键筛选了train/val，不能证明CPP物理来源日期也被隔离。这进一步削弱旧R的日期隔离声明。此发现不等于读取了test GHI；本次仅重算既有路径/资格清单，没有新打开缓冲日或测试日数值文件。

## 后续处理

1. 使用修正后新四组的同期validation结果时，完整说明其2,195条验证支持、共同容量和三seed；不沿用旧AL或AP结论替代新实验的表示归因。
2. 如用户恢复未来预报工作，需按原五折训练日期重建正确CPP监督、重训五个fold-R，重做训练OOF COT及full-train R验证COT，再从头训练同设置FA/FAC并配对评分。仅平移评分时刻无法修复已经训练出的旧权重。
3. SimVP的AGRI监督本身不依赖R的CPP标签，此次错配不自动使其AGRI模型或已核验预测场失效；能否复用仍需按原日期/归一化/权重来源核对。A/AP/FA/FAP的数值也不直接由错时R产生，但与受影响臂的COT科学解释要撤回。
4. 当前实验停止指令继续有效；本次没有新训练或自动续跑。
