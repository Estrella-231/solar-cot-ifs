# 四里2024-09-05无效GHI观测日排除

2026-10-19。依据用户本次明确确认：“数据中有一天34条数据全都是0，是数据问题，把这一天去掉”。确认目标为四里站北京时间2024-09-05，实施站点整日排除，而不是依照预测误差筛选记录。原始观测、旧数组和模型权重保留。没有重新训练、重新选checkpoint或读取test。

## 核对结果

- 此前34条是满足“持续零值且晴空辐射较高”等条件的15分钟标签计数，不是该日全部标签数。
- 原始标签清单中，四里该日39条记录全部GHI=0，全部属于validation；没有其他split的标签被此次规则移除。
- 当前三帧数据要求同日上下文，包含其中37条，37条真值均为0。因此当前4263条验证记录减至4226条；较早单帧4479条减至4440条。
- 保存的原工作簿回查记录覆盖该日06:00–16:00共121个5分钟单元格，121个全为0，缓存与源表一致。原持续零值事件起于前一天22:20，结束于该日16:00，含213个连续5分钟记录。这里并未重新联网读取全天源文件，不能将121条回查说成288条完整日观测。
- 设备故障/占位零等具体原因未独立认定；按照用户对该日无效的确认进行质量排除，不再要求外部证书才能执行。

## 实际修改与产物

1. `docs/GHI_STATION_DAY_EXCLUSIONS_20261019.json`：保存唯一排除项`(sili,2024-09-05)`及用户确认依据。
2. `scripts/station_day_quality.py`：通过站点、BJT目标日期生成所有方法共用的keep mask；UTC时间显式转换BJT。不能按init日期代替target日期。
3. 本目录`excluded_GHI_label_rows.csv`保存39条排除记录；`ghi_rows_source_dayclean_trainval.csv`保存该原train/val标签清单的整日清洗版。其他训练/验证日期和竺家同日未删。
4. 四套保存预测分别产生独立`*_dayclean.npz`及`*_keep_mask.npz`，所有方法/种子沿同一个样本轴筛选。
5. 子项目AGENTS已登记该质量规则，后续GHI构建与评价复用；旧数据包和已运行任务没有在原位置被替换。对要求两站共同完整日的日累计评价，该无效日应退出共同完整日比较，但不将竺家源数据标为故障。

本规则只判断GHI观测有效性，不表示当天卫星AGRI或CPP也有问题，故不直接删除S/R的独立卫星监督样本。也未自动扩大到四里其他连续零日或竺家的可疑零值。

## 固定权重复算

RMSE单位W/m²；每站各seed独立算RMSE，再对两站和三seed等权。bootstrap为2000次共享BJT目标日期块配对重采样、随机种子20261019；使用筛选后实际日期并集。当前三帧实验从52日减至51日，四里43日、竺家50日；该队列本来没有竺家2024-09-05记录，规则未禁止或删除竺家同日。较早单帧队列也从52日减至51日。具体日期数以RESULTS.json为准。这些区间条件于旧验证选模，不是重新选模或独立test。

高透过加权实验同样整日排除后，原损失无COT/有COT为89.531/88.756，新损失无COT/有COT为90.784/89.401。故清洗该日也未使原先的固定2倍损失候选自动优于原损失。详细分数与区间见`RESULTS.json`，不把排除后的分数作为重训成绩。

## 后续使用

复算入口：`python audits/sili_invalid_day_20261019/apply_and_rescore.py`。脚本核对排除行全零、split、源回查及竺家不被删除，并记录每套输入预测文件和规则的SHA256。结论为“用户确认的无效站点日已建立整日排除规则，并完成四套固定权重评价清洗”，不等于整项目所有其他疑似观测问题均已解决。
