# CPP晴空处非零R-COT为何有用：时间支持、云影与标签源核查

## 当前判断

不是一个统一原因。已经找到**瞬时/短区间云况与15分钟标签不一致**的直接证据；没有找到把标签平均算错或北京时间/UTC错8小时的证据。云影仍可能影响部分事件，但本轮不足以认定它是主因。另发现一类不能解释成云物理收益的情况：原工作簿在白天持续写0，恢复非零R值让模型向0靠近，从评分上看改善，但物理正确性并未得到证明。

因此，上一轮“CPP晴空位置的非零COT对GHI有用”应严格理解成：**固定模型对连续R表示存在统计依赖**，并非证明这些位置真的有相应云厚度。

## 读取与复核范围

1. 对全部8,994条月度val标签检查BJT/UTC、记录时刻、三条5分钟记录和15分钟平均。其中8,137条完整均值最大重算差为3.34×10⁻⁹ W/m²，未发现时间戳重复冲突。
2. 在FD-201直接重读原工作簿：每站114个指定验证日期的5分钟单元格；其中四里95个、竺家114个可与现有标签源重合对照，逐值完全一致。其余是验证日期内事件窗口的诊断补充，未补入正式主队列；不读取test测量载荷。
3. 在FD-201直接读取6个事件原始HDF的`NOMObs/NOMObsTime`，使用grid_static真实HDF行列694/1554（四里）或612/1549（竺家）；原值与现有aux扫描偏移差<0.001秒。没有把16×16的站点索引当HDF索引。
4. 读取同刻原始CPP文件中的CLP/COT/CTH，并按经纬度索引到16×16；共同有效像元与此前缓存逐值一致。实际文件有CLP/COT/CTH/CER，却没有CTH单位属性与独立QA层。
5. 图中真实AGRI为当前源缓存的实测通道，固定C03/C02/C01假彩色。读取6例前后共28个可用AGRI/aux窗口；没有生成合成云场，没有改变正式标签或重新训练。

## 1. 时间链路：没有查到平均错误，但有明确的观测支持差异

当前标签覆盖 `(T−15min,T]`，由结束时刻为T−10、T−5、T的三条5分钟区间记录平均而成。原生5分钟值也不是瞬时测量。

6例真实扫描均发生在名义T之后：四里约184.35秒（3分04秒），竺家约159.47秒（2分39秒）。也就是说，图像与15分钟标签中心相隔约10–10.6分钟。

这是真实扫描和标签窗口的支持不同，不是已发现的标签偏移编码错误。不能因此将全部标签自动后移3分钟或15分钟。

### 四里2025-07-08 14:30 BJT

| 数据 | GHI（W/m²） |
|---|---:|
| 14:20结束的5分钟记录 | 316 |
| 14:25结束的5分钟记录 | 265 |
| 14:30结束的5分钟记录 | 1002 |
| 正式15分钟标签 | **527.67** |
| 包含14:33:04实际扫描的5分钟区间（14:35结束） | **962** |

同刻CPP站点CLP=0、COT=0；上一张14:15名义图的站点CLP=1。原始记录支持该区间内经历了强烈遮蔽变化：当前图像晴空与当前短区间GHI较高是一致的，但不能代表此前15分钟一直晴空。

因此，这一事件不必诉诸“当前晴空像元正被异地云影遮蔽”才能解释。连续R-COT的邻域与上下文可能帮助当前头回归较低的区间标签，但目前尚未证明它在编码此前遮蔽轨迹。

![四里时间支持](figures/case0_sili.png)

### 竺家2024-09-04 14:00 BJT

13:50、13:55、14:00的原始记录分别为216、241、843 W/m²，正式标签433.33；实际扫描14:02:39所在5分钟区间为642。当前CPP站点CLP=0，但3×3并非全晴。

门控头813.79，恢复CPP晴空位置原R值后605.21 W/m²。这是另一例强烈区间变化：当前晴空类别不能替代整个15分钟的遮蔽状态。恢复值带来的评分收益也不能据此等同于恢复了真实光学厚度。

## 2. 15分钟平均不能解释所有竺家事件

竺家2025-07-08 13:30 BJT是中心3×3全部CPP晴空、恢复CPP晴空处R值收益最大的事件：

- 三条记录426.05、430.77、445.05；平均433.96 W/m²。
- 实际13:32:39扫描所在5分钟区间449.86。相对于模型误差，平均与扫描附近短区间的差别很小。
- 门控头746.60；恢复CPP晴空处R值后663.90。仍明显高于原记录。

该例不能用“把15分钟平均换成末帧就解释了”来处理。CPP分类/像元代表性、实际云影、站点辐射记录本身及连续R表示的代理作用仍需区分。

![竺家低变化事件](figures/case1_zhujia.png)

分层结果也支持原因不统一：中心3×3全部CPP晴空的样本中，竺家112个非零、低变化样本（区间内最大−最小≤25 W/m²）几乎贡献了该纯晴空子集全部恢复收益；高变化16个样本的净恢复收益反而为负。因此不能将所有竺家收益归于15分钟平均。

## 3. 云影：做了方向和视差诊断，目前没有足够证据定案

独立调用已存档pvlib 0.9.1的NREL SPA模块，按真实UTC扫描时刻和站点经纬度计算太阳位置。直接加载SPA模块，避开旧pvlib整体导入与新版SciPy的兼容问题，没有改动全局环境。

几何诊断使用局部东/北平面。若站点O受到高度h的云遮蔽，该云在未做视差修正的卫星表观网格上的候选位置近似为：

\[
P(h)=O+h\tan(z_\odot)u_\odot-h\tan(z_v)u_v.
\]

其中u为相对于正北顺时针方位角的水平单位向量；同时展示不含视差的太阳方向和反向对照。太阳与卫星视差必须同时考虑，单纯沿太阳方向移动云图可能误判；方法依据见[AMT原始研究](https://amt.copernicus.org/articles/18/3917/2025/index.html)。

本轮只检查0.5–15 km云高假设下的候选位置，不在验证误差上搜索最佳移动量，不移动标签。原CPP的CTH数值范围与常见km云高相似，但文件没有units，现有Portable代码的0–17.5输出范围也不能证明该历史文件的单位与生产来源，因此**没有把CTH当作已确认的km高度**。

| 案例 | 加视差后COT≥3候选云的最近横向距离 | 所需假设高度 | CPP同像元CTH数值（单位未确认） |
|---|---:|---:|---:|
| 四里2025-07-08 14:30 | 0.50 km | 9.65 km | 2.39 |
| 竺家2025-07-08 13:30 | 3.66 km | 13.63 km | 1.84 |
| 竺家2024-09-04 14:00 | 9.85 km | 6.07 km | 9.77 |
| 竺家2025-06-16 14:45 | 14.94 km | 13.76 km | 8.44 |

这些是站点周围16×16、原分辨率约4 km网格上的敏感性结果。首例有方向上接近的候选云，但所需高度与CTH数值并不自然吻合；若历史CTH确实以km表示，则该特定像元也未形成一致的高度证据。后两例没有找到贴近几何走廊的厚度≥3云像元。受像元尺度、薄云、多层云、局地视场及云高单位不明限制，不能据此排除云影，但也不能将它当作已查明的主因。

另发现源太阳角与按真实扫描时刻重算的SPA仍有差异，选例中天顶角最大约2.83°。本次云影诊断使用独立SPA，没有把原角度链宣布为完全正确；也没有以这些角度重新反演R或训练头，故尚未量化它对本轮R/GHI的独立影响。

## 4. 新发现：部分“收益”受白天持续零值牵引

四里2024-09-05 16:00，CPP中心3×3全晴，源AGRI可读，但原工作簿在14:30–17:35所读取的38条5分钟记录全部为0。该日正式验证中有39条白天主标签为0；其中11条有CPP参考。

这说明零值不是本次打包时把NaN变成0，已经写在原工作簿中。但原文件没有提供足够的传感器状态来判定它是故障、停机占位，还是其他源问题，不能自动认定为无效并删除。

在四里中心3×3全CPP晴空的117个样本中，6个零标签样本（同一天）贡献的恢复净平方误差收益8685，大于该子集总收益8238；其余非零样本合计为负。也就是说，这一纯晴空子集的“恢复COT有用”，主要被这些可疑零值牵引，不能解释为云物理精度收益。

![四里白天零值](figures/case2_sili.png)

更广的CPP共同子集上，恢复晴空处R值的净平方误差收益集中在少数日期：四里7月8日和9月5日约占总净收益的101%（其他日期净抵消）；竺家9月4日和7月8日约占99.7%。这只是签名误差的集中度记账，不是物理归因比例，也不是跨日期稳定收益。

## 后续顺序

1. 保持正式对照结果只读，先审计两站白天零值/孤立零点的源语义与可用状态。另报不改变主队列的敏感性结果，不能只为改善指标而删点。
2. 对强变化事件，优先设计有真实扫描支持的区间表示：历史/当前局地AGRI与COT共同描述过去15分钟的遮蔽变化，保持正式15分钟目标定义；不能用统一后移标签来修指标。
3. 对竺家7月8日这类低变化但CPP晴空、GHI持续偏低的事件，先核实站点辐射记录与CPP类别，再补齐可信云高单位/生产来源与云影几何；当前没有充分证据直接设计“确定云影修正”。
4. 保留连续R表示，不自动重启硬清零或扩种子。所有新模型或目标修订另立合同；本次未新增训练、未读test、未修改论文正文。
